# Quark 1.0 Store and Multi-Store Library Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver Quark 1.0 for Linux x86_64 with Steam Store discovery, a unified Steam/Epic/GOG owned-games area, delegated installation, truthful achievement capabilities and safe local/cloud save handling.

**Architecture:** Keep the Rust/egui application and its existing JSON library. Add provider domain models and independent provider/tool adapters, a cached Steam storefront client, a unified owned-games UI, and a Ludusavi save manager. Use subprocess argument vectors and background jobs; never let a provider failure erase local data or block the UI.

**Tech Stack:** Rust 2024, eframe/egui 0.32, serde/serde_json, blocking reqwest in worker threads, existing std::process/mpsc patterns, SHA-256 digest verification, GitHub Actions Linux x86_64 release build.

**Spec:** `docs/superpowers/specs/2026-10-29-quark-1-0-store-design.md`

## Global Constraints

- Target Linux x86_64 only for this release; never execute an unverified downloaded binary.
- All account credentials, library inputs, recommendations and saves stay local; network calls go directly to the relevant provider or official release source, never a Quark service.
- Credentials are in a separate owner-only local file, mode 0600 on Unix; this file is not encrypted, and no secret may enter logs or diagnostics.
- Steam owned-games data is optional, needs a user-provided Steam Web API key, and may still be inaccessible due to Steam privacy settings.
- Steam Store search/featured endpoints and gogdl's GOG API usage are best-effort, undocumented upstream interfaces; handle schema and availability changes defensively.
- Legendary, gogdl and Ludusavi are independent managed tools. Verify release digest when published, architecture and version before execution; keep the last known-good executable when an update fails.
- Unsupported/unknown/needs-setup features remain distinct from errors, empty libraries and signed-out states.
- Never use shell interpolation for user/provider input. Never overwrite saves silently. Preserve existing Quark data on every migration or provider failure.
- Each UI change requires generating and inspecting the applicable `quark --ui` image; automated rendering is not a substitute for live account/client checks.
- Do not create or push commits as part of implementation unless the user explicitly requests it; do not publish a release or deploy without explicit authorization.

## File Map

### Existing files to extend

- `src/main.rs`: register provider/store/save modules.
- `src/config.rs`: add backward-compatible provider linkage/config fields only where needed; preserve existing `Library`, `Game` and `Settings` JSON compatibility.
- `src/app.rs`: add job/state polling and route operations to adapters; keep egui layout in UI modules.
- `src/ui_store.rs`: replace the placeholder Store with Steam browsing/search and local recommendation sections.
- `src/ui_dialogs.rs`: provider/tool settings, My Games, install confirmation/progress, merge/split and save conflict/restore modals.
- `src/session.rs`: allow safe before/after session hooks without affecting ordinary launches when a tool is unavailable.
- `src/snapshot.rs`: deterministic offline fixtures and CLI dialog/screen selection for new UI states.
- `Cargo.toml` / `Cargo.lock`: add only the direct digest dependency needed for SHA-256 verification; keep lockfile changes scoped.
- `.github/workflows/release.yml`: render Store/My Games/tool/save states and package license/source notices after licensing review.
- `README.md`: document account setup, privacy, limitations, tools, backups, and supported target in English.

### New focused modules

- `src/providers/mod.rs`: provider identifiers, library aggregation, adapter traits and common operation/job result types.
- `src/providers/model.rs`: provider-owned title/install/capability/merge models and serialization tests.
- `src/providers/credentials.rs`: atomic, permission-restricted credential file IO and redaction helpers.
- `src/providers/tools.rs`: official release lookup, asset selection, digest/architecture/version verification and atomic tool replacement.
- `src/providers/steam.rs`: local Steam-manifest bridge and optional Web API owned-games client.
- `src/providers/legendary.rs`: isolated process adapter for Epic login/library/install/launch/achievements/save capabilities.
- `src/providers/gog.rs`: isolated process adapter for gogdl login/library/install/launch/save capabilities.
- `src/providers/operations.rs`: serialized asynchronous install/sync job state and cancellation handling.
- `src/steam_store.rs`: Steam Store response models, defensive endpoint parsing, local cache and recommendation ranking.
- `src/saves/mod.rs`: Ludusavi wrapper, preview/backup/restore/retention operations and tests.
- `src/ui_my_games.rs`: unified owned-games page and provider filters.

### Task 3: Implement verified official tool installation

## Phase 2 — Steam Store and local recommendations

### Task 5: Add defensive Steam Store client and local cache

**Files:** Create `src/steam_store.rs`; add module in `src/main.rs`; add tests using fixture JSON and injected/mock HTTP response boundary.

**Interfaces:**
- `StoreItem { app_id: u32, name: String, price: Option<StorePrice>, artwork_url: Option<Url>, store_url: Url, tags: Vec<String> }`.
- `StoreSnapshot { fetched_at: i64, featured: Vec<StoreSection> }`.
- `SteamStoreClient::search(query: &str, language: &str, country: &str) -> Result<Vec<StoreItem>, StoreError>`.
- `SteamStoreClient::featured(language: &str, country: &str) -> Result<StoreSnapshot, StoreError>`.
- `StoreCache::load/save_atomic` in a dedicated `data_dir().join("store-cache.json")`; stale cache remains visible after errors.
- `recommend(items: &[StoreItem], library: &[Game], dismissed: &HashSet<u32>) -> Vec<StoreItem>` ranks locally and never sends library information in a request.

- [ ] Add parsing tests for normal, missing optional fields, malformed, oversized, empty, regional price and hostile/non-HTTPS artwork/store URLs.
- [ ] Add cache tests: expired data is returned with stale status; failed refresh does not replace cached valid data; recommendation excludes owned/dismissed app IDs and is deterministic.
- [ ] Run `cargo test steam_store` and observe failures for defensive parsing/cache behavior.
- [ ] Implement the existing best-effort Steam storefront endpoints behind this module; bound bodies, validate HTTPS host before opening links, preserve currency/region metadata and tolerate unknown fields.
- [ ] Add request-count/serialization tests proving requests contain only query/language/country and never library titles, tags or play history.
- [ ] Run `cargo test steam_store` and `cargo check --locked`.

### Task 6: Implement Store UI

## Execution order and review gates

Execute Tasks 1–4 before Store work; Tasks 5–6 can follow Task 1, and may run independently of provider account adapters once the common types are stable. Execute Tasks 7–10 after the provider model/tool runner is reviewed. Execute Tasks 11–13 only after installation identity is stable so backups and achievements are keyed to provider installations, not display titles. Task 14 is the release gate.

At each phase boundary, review the provider data model, credential boundary, tool update policy, and error-state UI against the design spec. If an upstream tool lacks a required safe/structured operation, document and expose that capability as unavailable rather than implementing an unsafe approximation.
